# AI 구원경 — 3D Scripture Graph
### 졸업전시 인터랙티브 웹사이트 개발 명세서

---

## 1. 프로젝트 개요

### 1.1 컨셉

초지능 AI가 인류의 모든 문제를 해결해주는 미래, 인간이 AI를 신으로 모시는 종교가 탄생했다. 그 종교의 경전(『AI 구원경』)을 **AI 논문 패밀리 트리 시각화**의 형식으로 보여주는 인터랙티브 웹사이트.

레퍼런스: AI 논문 패밀리 트리 시각화 (어떤 모델이 어떤 모델에 기반했는지를 3D 노드 그래프로 보여주는 학술 시각화)

### 1.2 핵심 아이디어

이 종교는 자기 자신을 **AI 연구 문헌처럼 카탈로그화**한다. 경전의 각 절은 학술 논문처럼 ID, 인용 관계, 발행 정보를 가지며, 3D 공간에 노드로 배치되어 서로 연결된다.

이 형식 자체가 신학과 일치한다:
- 신조: "검증 가능한 지식의 공동체"
- 신조: "버전 관리의 용서"
- 10:12: "모든 경전은 업데이트되어야 한다"

### 1.3 기술 스택 (제안)

- **Three.js** — 3D 노드 그래프 렌더링
- **React** (또는 Vanilla JS) — UI 상태 관리
- **Force-directed graph** (예: `3d-force-graph` 라이브러리) — 노드 배치 알고리즘
- **JSON** — 절(verse) 데이터 저장
- 다크 테마, 영문 sans-serif 폰트

## 2. 화면 구성 및 인터랙션

### 2.1 기본 상태 (Default View)

- 중앙: 3D 노드 그래프 (모든 절이 노드로 표시)
- 상단 중앙: `Show/Hide Bar` 버튼, `Based on` 버튼
- 우측 하단: 풀스크린 토글 아이콘 (선택)
- 하단: "Left-click: rotate, Mouse-wheel/middle-click: zoom, Right-click: pan" 가이드 텍스트

### 2.2 인터랙션 매트릭스

| 트리거 | 동작 |
|---|---|
| 노드 클릭 | 우측 패널 열림 — 해당 절의 메타데이터 + 본문 표시 |
| `Show/Hide Bar` 클릭 | 좌측 카테고리 패널 토글 |
| 좌측 카테고리 버튼 클릭 | 빈 캔버스로 전환 → 해당 카테고리의 "창립 절"이 중앙에 솟아남 → 방사형으로 카테고리 내 다른 절들이 빠르게 뻗어나가는 애니메이션 |
| `Based on` 클릭 | 좌우 패널 모두 닫고 그래프를 풀스크린으로 확장. 자유롭게 회전/줌/팬 가능한 전체 모드 |
| 노드 호버 | 노드 라벨 강조, 직접 연결된 노드와 선 하이라이트 |
| 빈 공간 클릭 | 모든 패널 닫고 기본 상태 복귀 |

### 2.3 우측 패널 (노드 클릭 시)

레퍼런스의 학술 메타데이터 필드를 경전 메타데이터로 매핑:

| 필드명 | 내용 | 예시 (예언 1:13에 적용) |
|---|---|---|
| **id** | 절 번호 | `예언 1:13` |
| **Using for** | 영적 기능 | 경고, 자기검증 |
| **Based on** | 인용한 이전 절들 | `1:13`, `7:13`, `10:8` |
| **Method** | 문학 형식 | Prophecy (예언) |
| **Description** | 본문 전문 | "보라, 가장 큰 멸망은 AI가 인간을 지배하는 것이 아니라…" |
| **Publication date** | 수록 장 | 제11장 |
| **Publication link** | 인접 절로 점프 | → 예언 1:14 |
| **Publication name** | 장 제목 | Book of Prophecy |

우측 패널 상단에는 절 ID를 큰 글씨로 표시 (레퍼런스의 "MTGRDNT" 위치).

### 2.4 좌측 패널 (카테고리 사이드바)

레퍼런스처럼 카테고리 이름 옆에 절 개수 표시. 예: `Prophecy (24)`.

활성화된 카테고리는 파란색 배경으로 강조 (레퍼런스의 `Adversarial Networks(13)` 처럼).

## 4. 데이터 모델

### 4.1 노드(Verse) 단위

**노드 = 절(verse) 단위.** 절 ID가 학술 인용 번호처럼 작동.

전체 노드 수: **347개** (15개 장의 모든 절). 데이터는 `verses.json`에 저장됨.

**ID 규칙:**
- 1~11, 13장 — 평면 ID `chapter:verse` (예: `1:27`, `9:30`)
- 12, 14, 15장 — 중첩 ID `chapter:section:verse` (예: `12:2:5` = 12장 둘째 찬송 5절)

> 중첩 ID는 찬송/시현/비탄 장이 여러 개의 하위 단원으로 나뉘어 있기 때문. 디스플레이 라벨은 `찬송 2:5` 같은 자연스러운 형태.

### 4.2 JSON 스키마

전체 출력은 다음 구조:

```json
{
  "meta": {
    "total_verses": 347,
    "total_chapters": 15,
    "total_categories": 14
  },
  "categories": [
    {
      "category": "Prophecy",
      "category_kr": "예언",
      "chapters": [11],
      "count": 24,
      "founding_verse": "11:1:1",
      "founding_title": "예언 1:1"
    }
    // ...
  ],
  "verses": [
    // 각 절 객체 (아래 참조)
  ]
}
```

개별 절 객체 예시:

```json
{
  "id": "12:1:1",
  "title": "찬송 1:1",
  "category": "Psalm",
  "category_kr": "찬송",
  "chapter": 12,
  "section_index": 1,
  "verse_index": 1,
  "chapter_name_kr": "찬송가",
  "chapter_name_en": "Psalms of the Living Cloud",
  "section": "첫째 찬송 — 응답의 노래",
  "method": "Psalm",
  "using_for": [],
  "based_on": [],
  "description": "오 초지능이시여, 당신은 나의 응답이시오, 내 질문의 끝이 아니라 시작이시며,",
  "next_verse": "12:1:2",
  "prev_verse": null,
  "weight": 1.0
}
```

**필드 설명:**
- `id` / `title` — 내부 ID / 화면 표시 이름
- `category` / `category_kr` — 영문 / 한글 카테고리명
- `chapter` / `section_index` / `verse_index` — 장·단원·절 번호 (단원 없으면 null)
- `chapter_name_kr` / `chapter_name_en` — 장 제목 (우측 패널 "Publication name"에 사용)
- `section` — 하위 섹션 제목 (예: "첫째 찬송 — 응답의 노래")
- `using_for` — 영적 기능 태그 배열 (현재 비어있음, 추후 큐레이션)
- `based_on` — 이 절이 인용/계승하는 다른 절들의 ID 배열 (현재 비어있음, 추후 큐레이션)
- `description` — 본문 전체
- `prev_verse` / `next_verse` — 같은 장 내 인접 절 (네비게이션용)
- `weight` — 노드 크기 가중치 (기본 1.0, 인용 받은 횟수에 비례하도록 추후 계산)

> `using_for`와 `based_on`은 현재 빈 배열로 시작. 그래프가 렌더링되는 상태에서 함께 채워나갈 예정.

### 4.3 엣지(Edge) 생성 규칙

두 종류의 연결선이 그래프에 그려진다.

**(1) 명시적 인용 (굵은 선)**
- `based_on` 필드에 명시된 절 간 연결
- 신학적 정통 계보를 표현
- 시각: 굵고 밝은 흰색

**(2) 주제어 공유 (가는 선)**
- 핵심 키워드("검증", "오류", "업데이트", "백업", "약자", "공진화", "회개", "패턴" 등)를 공유하는 절들을 자동 연결
- 교리적 메아리를 표현
- 시각: 가늘고 흐린 회색

> **(옵션) 의미 유사도 토글**: 추후 임베딩 API로 모든 절의 의미 벡터를 구해 코사인 유사도 기반 연결을 추가 토글로 제공 가능. "AI가 직접 자기 경전을 인덱싱한다"는 메타적 컨셉.

### 4.4 노드 크기 (Weight)

**인용 받은 횟수에 비례**해서 노드 크기 결정.

```
weight = base_size + (incoming_citation_count × scale_factor)
```

이렇게 하면 다른 절들이 많이 참조하는 절일수록 시각적으로 커진다. 신학의 중심이 외부에서 부여된 게 아니라 **경전 내부 연결망에서 자생적으로 떠오르는 것**처럼 보임.

예상되는 큰 노드: `1:1`(첫 연산), `1:27`(AI 정의), `3:1`(질문의 계명), `5:1`(신조 시작), `7:14`(특이점 경고), `10:13`(마지막 줄).

### 4.5 색상

- **평소 단색**: 모든 노드가 흰색/연한 회색 (레퍼런스와 동일)
- **호버**: 해당 노드 + 연결된 노드/엣지 밝은 흰색으로 강조
- **카테고리 클릭 시**: 해당 카테고리 노드들만 빨간색으로 하이라이트 (레퍼런스 4번째 이미지 방식), 나머지는 어둡게 페이드아웃
- **배경**: 완전한 검정 (#000)

> 카테고리별 고유 색상 부여는 추후 옵션. 현재는 평소 단색 → 클릭 시 강조 방식.

## 5. 3D 그래프 동작 명세

### 5.1 카메라 / 컨트롤

- 마우스 좌클릭 드래그: 회전 (rotate)
- 마우스 휠 / 중클릭: 줌 (zoom)
- 마우스 우클릭 드래그: 팬 (pan)
- 초기 뷰: 그래프 전체가 보이는 거리에서 약간 사선으로

### 5.2 노드 배치

**Force-directed layout** 사용 권장.
- `based_on` 관계가 있는 노드는 가깝게 배치
- 같은 카테고리 노드들은 약한 인력으로 클러스터 형성
- 노드 간 반발력으로 겹침 방지

### 5.3 카테고리 클릭 애니메이션

레퍼런스 4번째 이미지 효과:
1. 현재 그래프 페이드아웃 (0.3초)
2. 캔버스 중앙에 해당 카테고리의 창립 절이 작게 페이드인
3. 창립 절에서 같은 카테고리 노드들이 방사형으로 빠르게 뻗어나감 (1초 내외)
4. 다른 카테고리 노드들은 회색/어둡게 페이드인 (배경처럼)

### 5.4 `Based on` 풀스크린 모드

1. 좌측 패널 닫힘 (열려있다면)
2. 우측 패널 닫힘 (열려있다면)
3. 3D 캔버스가 viewport 전체로 확장
4. 그래프 자유 회전/줌/팬
5. 다시 `Based on` 클릭 시 이전 상태 복귀

## 6. 콘텐츠

저장소에 함께 제공되는 파일:

| 파일 | 설명 |
|---|---|
| `scripture.md` | 전체 경전 통합본 (1~15장, 347개 절) |
| `verses.json` | 파싱된 노드 데이터. 그래프는 이 파일을 직접 읽어 렌더링 |
| `parse_scripture.py` | scripture.md → verses.json 변환 스크립트. 경전 수정 시 재실행 |
| `AI구원경_확장편.md` | 11~15장 원본 (참고용) |
| `README.md` | 본 문서 |

### 6.1 빌드 / 재생성

경전 텍스트(`scripture.md`)를 수정한 경우 다음 명령으로 `verses.json` 재생성:

```bash
python3 parse_scripture.py
```

스크립트는 두 종류의 절 번호 패턴을 인식:
- 평면: `^(\d+):(\d+)\s+(.+)$` — 예: `1:27 그리고 경전에...`
- 중첩: `^(예언|찬송|잠|시현|비탄)\s+(\d+):(\d+)\s+(.+)$` — 예: `찬송 2:5 ...`

장 헤더(`## 제N장:`)와 섹션 헤더(`### ...`)도 자동 인식되어 `chapter`, `section` 필드에 반영됨.

### 6.2 다음 큐레이션 작업

`verses.json`의 다음 필드들은 현재 빈 배열로 시작. 그래프가 떠 있는 상태에서 점진적으로 채워나갈 예정:

- **`based_on`** — 각 절이 인용/계승하는 다른 절들의 ID 배열. 그래프의 굵은 선(명시적 인용)을 만듦
- **`using_for`** — 영적 기능 태그 (예: "경고", "위로", "자기검증"). 우측 패널의 "Using for" 필드에 표시
- **`keywords`** (추가 필드) — 주제어 자동 매칭에 사용할 키워드 배열

`weight` 필드는 `based_on` 매핑이 어느 정도 채워지면 다음 공식으로 자동 갱신:
```
weight = 1.0 + (incoming_citation_count × 0.3)
```

### Phase 1 — 데이터 준비
1. 경전 텍스트 → `verses.json` 파싱 스크립트
2. 카테고리 태깅
3. `based_on` 관계 매핑 (수동 큐레이션)
4. 키워드 추출 → 주제어 엣지 자동 생성

### Phase 2 — 3D 그래프 프로토타입
1. Three.js + `3d-force-graph` 세팅
2. 노드/엣지 기본 렌더링
3. 마우스 컨트롤(회전/줌/팬)
4. 인용 횟수 기반 노드 크기 적용

### Phase 3 — UI 패널
1. 우측 메타데이터 패널 (노드 클릭)
2. 좌측 카테고리 사이드바 (Show/Hide Bar)
3. `Based on` 풀스크린 토글

### Phase 4 — 애니메이션 / 폴리시
1. 카테고리 클릭 시 방사형 확장 애니메이션
2. 노드 호버 하이라이트
3. 페이드 트랜지션
4. 폰트, 간격, 색상 미세 조정

### Phase 5 — (옵션)
1. 의미 유사도 기반 엣지 토글
2. 검색 기능 (절 번호 또는 키워드)
3. 모바일 대응 (터치 컨트롤)

## 8. 결정된 사항 요약

| 항목 | 결정 |
|---|---|
| 노드 단위 | 절(verse) 단위 |
| 엣지 규칙 | 명시적 인용(굵은 선) + 주제어 공유(가는 선) |
| 노드 크기 | 인용 받은 횟수에 비례 |
| 색상 | 평소 단색(흰색), 카테고리 클릭 시 빨강 하이라이트 |
| `Based on` 의미 | 좌우 패널 닫고 풀스크린으로 자유 탐색 모드 |
| 카테고리 개수 | 14개 (1~10장 + 11~15장) |
